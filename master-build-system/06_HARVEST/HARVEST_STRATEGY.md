# Harvest Strategy

Before coding a subsystem, inspect approved candidates in the registry. Preferred order:

1. ADOPT a maintained dependency/standard.
2. WRAP it behind a VibeFlow interface.
3. BRIDGE incompatible providers/standards.
4. EXTEND only where the extension remains separable.
5. BUILD only when VibeFlow's differentiating semantics are not available elsewhere.

VibeFlow should spend proprietary engineering effort on authority composition, grants/policy, durable remote semantics, recovery/reconciliation, provider normalization, mobile control and independent evidence/verification — not editors, terminal emulators, schedulers or generic protocol stacks that already exist.
